Принцип работы

1. Дерево держим стабильным и неглубоким. Не создаём десятки микрокатегорий вроде FASH.SHOES.SNEAKERS. Детализация живёт в type, фасетах и UI-branches.
2. APPAREL_COMMON — не категория товара. Это shared-слой для одежды. Он даёт общие атрибуты: размер, цвет, материал, fit, сезон, состояние, бренд.
3. MEN / WOMEN / KIDS наследуют APPAREL_COMMON. Они не дублируют базовые атрибуты, а добавляют свои defaults, aliases, route guards, user surface и правила размеров.
4. SHOES / BAGS / ACCESSORIES — отдельные production-ветки. У них другая логика: размеры обуви, типы сумок, типы аксессуаров, свои фасеты и свои правила маршрутизации.
5. Главный переключатель внутри ветки — type. Для одежды это apparel_type, для обуви shoe_type, для сумок bag_type, для аксессуаров accessory_type.
6. Branches внутри ветки — это UI/browse-группы. Например, “Кроссовки”, “Ботинки”, “Каблуки” внутри FASH.SHOES могут быть browse-группами, а не отдельными categoryCode.
7. Пользователь видит короткий user surface. Каталог может хранить много служебных данных, но UI показывает только нужное: тип, бренд, размер, состояние, цвет и релевантные поля.
8. Route guards защищают ветки от смешивания. “мужские кроссовки” → FASH.SHOES, “детский рюкзак” → FASH.BAGS, “женское платье” → FASH.WOMEN.
Короткое правило: categoryCode остаётся крупным и стабильным, а детализация переносится в type, фасеты, aliases, user surface и route guards.
